2. The core journey: question → answer#

  • Every answer — a refusal included — is durably persisted under a deterministic share_id (SHA-256 prefix of the normalized question) before the response returns, so /a/<share_id> can never race its own lookup.
  • Submit navigates to /a/<share_id>, which owns the full result experience (loading skeleton, retry, not-found, share); the homepage stays a discovery surface. This is the target behavior search-results-audit.md called for, now shipped.
  • The card shows no SQL, no parsed spec and no audit verdict: the server redacts all three before the answer crosses the wire, so there is nothing on the client to disclose.

Answer drill-downs#

Result rows link onward: player names → /players/[id], teams → /teams/[id], single games → /games/[gameId]. Answers about one player/team re-tint the accent system to that team's colors (see DESIGN_BRIEF.md §3).

3. Browse journeys#

Scoreboard loop — / ticker or /scores → pick season/week → game card → /games/[id] summary → box-score tab → tap a stat line → /players/[id].

Standings loop — /standings → season picker → division tables → team → /teams/[id] → schedule row → box score.

Leaders loop — /leaders (defaults to latest loaded season) → board row → player profile → splits/game-log tabs → questions about that player via search.

Fantasy loop — /fantasy → sort/filter player pool (position, per-game rates) → fill lineup slots → player links for due diligence.

Facts loop — the Fact of the Day card sits second on the dashboard, directly under the featured matchup, because a surprising number is the most repeatable reason to come back. "More facts" → /facts archive (most surprising first) → "Check the numbers" re-runs the fact as a search, landing on /a/<share_id>; player facts also link straight to the profile. /facts is not in the nav — the home card is its doorway.

4. Assistant flow#

The assistant never free-generates numbers — it routes to the same trusted endpoints and reports which tools it used. mode: "demo" is not a placeholder for a smarter mode: the LLM tool-calling layer was dropped, so routing is the whole product. The page itself is behind a Pro paywall until the flag flips, so most users meet the upsell rather than the chat.

5. Share flow#

  1. Any answer already lives at /a/<share_id>; its "Share" button copies that URL and reads "Link copied" for two seconds.
  2. Recipient opens /a/<share_id> → server fetches the persisted AnswerResult → same AnswerCard experience, no recomputation.
  3. The route-level action bar (New search · Share) has shipped; a clean PNG export of the rendered card is still planned (Track C in ENGINEERING_PLAN.md).
